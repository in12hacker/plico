# R3.1 — Portable MCP Test Harness

Status: DELIVERED | Base: `3e2a7c2` (v53 R3 acceptance) | Date: 2026-08-18

## Problem

`src/mcp/tests.rs` derived the server binary path as
`CARGO_MANIFEST_DIR` + a hardcoded debug-target segment. The v53 local gates
build into an external `CARGO_TARGET_DIR`, so all 8 library tests that spawn
the real `plico-mcp` subprocess failed with `Spawn(NotFound)`. This was a
test-infrastructure defect: the MCP protocol, the production client, and the
server binary were all correct.

## Changes

| File | Change |
|------|--------|
| `src/mcp/tests.rs` | Deleted `plico_mcp_bin()` and every hardcoded binary-path derivation. The seven subprocess tests moved out; `kernel_add_tool_provider_uses_typed_names` stays as a pure unit test over an in-memory fake `ExternalToolProvider` (no new production API). `cargo test --lib` now spawns zero MCP binaries. |
| `tests/mcp_client_test.rs` | New integration target with the seven migrated typed-client tests (server info, exact 14-tool catalog, object put/get, search typed diagnostics, unknown-tool typed error, `ExternalToolProvider` descriptors, provider `call_tool`). Assertions are unchanged from the library versions. |
| `tests/support/mod.rs` | Shared support: `PLICO_MCP_BIN` (`env!("CARGO_BIN_EXE_plico-mcp")` — Cargo's official mechanism, valid under any `CARGO_TARGET_DIR`) and `typed_client(root)` (TempDir `PLICO_ROOT`, stub backends, no network/model). |

| `tests/mcp_test.rs` | Unchanged by design: it already speaks raw JSON-RPC through its own self-contained harness and already used `CARGO_BIN_EXE_plico-mcp`; keeping it byte-identical preserves the review-frozen protocol-parity surface. |

## Harness layering (deviation note)

The unified harness requirements are met with one split: typed-client tests
spawn through the production `McpClient` (single spawn point in production
code; the server exits on stdin EOF — `serve_stdio` — which is the
production shutdown path, so the child is reaped without test-side kill
logic), while the raw protocol-parity file keeps its existing explicit
kill-and-wait lifecycle. A test-side second spawn implementation was not
added: within this delivery channel, any new direct `Command::new` call in
test code is rejected by the repository's code-write safety scanner
(command-injection heuristic fires on non-literal program paths), and the
production spawn path already provides the required lifecycle. No production
code was modified.

## Forbidden pseudo-fixes — compliance

- No `target/debug` / `target/release` search: `rg 'target/(debug|release)/plico-mcp' src tests` → zero hits.
- No manual `CARGO_TARGET_DIR` joining; no `cargo build` inside tests; no
  skip-on-missing-binary; `Spawn(NotFound)` is not in any allow-fail list.
- Production client (`src/mcp/client.rs`), the public protocol, Cargo
  dependencies, and the production binary are untouched (no Architecture
  Deviation required).
- No GitHub Actions.
